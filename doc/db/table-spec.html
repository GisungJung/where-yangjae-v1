개요 restaurants reviewers ratings rating_photos regions 뷰 함수·트리거 RLS Storage 변경 이력

1. 개요 · 관계

reviewers ─┬─< restaurants.registered_by (ON DELETE SET NULL) └─< ratings.reviewer_id (ON DELETE CASCADE) restaurants ──< ratings.restaurant_id (ON DELETE CASCADE) ratings ──< rating_photos.rating_id (ON DELETE CASCADE → Storage 객체 동반 삭제) regions ·· 식당과 FK 없음 — 지역은 좌표 최근접 기준점으로 파생 restaurant_stats (뷰) = restaurants ⟕ ratings(리뷰어별 최신 1건만 집계)

공통 규칙 — PK는 uuid DEFAULT gen_random_uuid() (regions만 name PK) · created_at/updated_at은 timestamptz DEFAULT now(), updated_at은 BEFORE UPDATE 트리거 자동 갱신 · 삭제는 soft delete(restaurants.status) 원칙, 클라이언트 DELETE는 RLS로 차단(ratings·사진 본인 것 제외).

5. RLS 정책 요약

"본인" = 클라이언트가 보낸 x-reviewer-id 헤더가 row의 reviewer_id(또는 reviewers.id)와 일치. 강한 보안이 아닌 어뷰징 1차 방지용 소프트 게이트. 대상 role: anon, authenticated.
